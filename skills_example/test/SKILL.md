# Go 单元测试编写

目标：写出**失败时能快速定位原因**的测试。测试的价值不在通过的那一刻，而在它失败的那一刻——一个失败的测试应该让人 10 秒内知道"哪里错了、错成什么样"。

## 核心原则

1. **测试行为，不测实现**。断言公开行为（输入→输出、副作用），不断言内部调用顺序。实现重构时测试不应该需要跟着改。
2. **每个测试只验证一件事**。一个用例失败就指向一个明确的问题；多件事挤在一个用例里，失败信息会互相淹没。
3. **错误路径和正常路径同样重要**。只测 happy path 的测试套件给出的是虚假的安全感。
4. **用标准库**。本仓库使用 `testing` 标准库，不引入 testify 等断言库；错误信息用 `t.Errorf` / `t.Fatalf` 手写，保持零依赖。

## 流程

### Step 1: 理解被测对象

1. 读被测代码，列出：
   - 公开行为：每个导出函数的输入→输出契约
   - 副作用：是否写文件、发网络请求、依赖全局状态
   - 依赖：需要注入或替换的外部依赖（时间、随机数、IO）
2. 看同包已有测试的风格（命名、辅助函数），**保持一致**

### Step 2: 设计用例

优先使用**表驱动**（table-driven）风格，这是 Go 社区标准做法：

```go
func TestParseSkillName(t *testing.T) {
    tests := []struct {
        name    string
        content string
        want    string
        wantErr bool
    }{
        {
            name:    "标准 frontmatter",
            content: "---\nname: review\ndescription: 测试\n---\n正文",
            want:    "review",
        },
        {
            name:    "缺少 frontmatter 时返回未知",
            content: "只有正文没有头部",
            want:    "Unknown Skill",
        },
        {
            name:    "name 带引号时剥掉引号",
            content: "---\nname: \"quoted\"\n---\n",
            want:    "quoted",
        },
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got := parseSkillMD(tt.content)
            if got.Name != tt.want {
                t.Errorf("Name = %q, want %q", got.Name, tt.want)
            }
        })
    }
}
```

**用例设计清单**（按顺序过一遍，每个问题要么有对应的 case，要么明确说明为什么不适用）：

- 正常路径：典型输入下期望的输出
- 空值/零值：空字符串、nil、空切片、0
- 边界：第一个/最后一个元素、刚好越界、单元素集合
- 非法输入：格式错误、类型不符——期望返回 error 而不是 panic
- 并发场景：被测对象被多 goroutine 同时使用时是否安全（必要时用 `-race` 验证）
- 重复/幂等：同一操作执行两次的结果

### Step 3: 处理外部依赖

| 依赖 | 处理方式 |
|------|---------|
| 文件系统 | 输入文件用 `t.TempDir()` 构造临时目录；或把数据做成内嵌字符串 |
| 时间 | 把 `time.Now` 抽成函数字段/参数，测试中注入固定时钟 |
| 网络/DB | 通过接口注入 fake 实现；没有接口就先和用户讨论是否值得为此重构 |
| 随机数 | 注入 rand 源，保证可复现 |

**不要**在单元测试里真实联网或连 DB——那是集成测试的职责。确实需要时，用 `testing.Short()` 或环境变量门槛控制，并在测试注释里说明。

### Step 4: 运行验证

```bash
go test ./internal/xxx/ -run TestXxx -v   # 先单跑新写的测试
go test ./internal/xxx/ -race             # 并发相关必须带 -race
go test ./...                             # 最后全量回归，确认没改坏别的
```

**验证标准**：新测试全部通过 + 全量回归通过。如果被测代码本身有 bug 导致测试失败，**不要改测试迁就代码**——向用户报告发现的问题，让用户决定修哪边。

### Step 5: 汇报

向用户报告：新增了哪些测试函数、覆盖了哪些场景（正常/错误/边界各几个）、`go test` 结果、发现的被测代码疑似问题（如有）。

## 反面清单

- 不写"测试自己 mock 自己"的循环断言（断言值来自复制实现逻辑）
- 不用 `t.Skip` 跳过写不出来的用例——写不出来说明设计有问题，说出来
- 不捕获测试中的 panic 继续跑（除非被测契约就是"不能 panic"）
- 输出信息不要只写 `got != want`，带上具体的 got 和 want 值
- 不为了凑覆盖率给 getter/setter 写测试；覆盖率是副产品不是目标
